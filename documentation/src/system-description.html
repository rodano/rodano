Introduction

This document describes how the Rodano platform works. Its purpose is to introduce readers to the main principles of the system without requiring them to work through all the technical details covered in the Technical specifications document.

System overview

Rodano is an electronic data capture (EDC) system for clinical trials. It is a highly configurable, web-based application that meets the regulatory requirements of Title 21 of the Code of Federal Regulations (CFR).

The platform is made up of a backend that exposes an HTTP API, several frontends that consume it, and supporting tooling:

  • Backend — a Java application, built on Spring Boot, that holds the data model, business logic, and HTTP API.
  • Main frontend — an Angular web application used by medical staff to capture and review study data.
  • Configurator — a JavaScript tool used by data managers to produce a study's configuration file.
  • ePRO — an Ionic and Angular mobile web application used by study subjects to report outcomes themselves.
  • Manager — a web application used to operate and maintain a Dockerized Rodano instance.

Backend

The backend is the server component that all frontends communicate with over its HTTP API. It manages access to the MariaDB database and enforces the study's business rules. Its main responsibilities are to:

  • authenticate users so that only authorized people can interact with the system;
  • validate incoming data, rejecting invalid values and reporting the errors back to the user;
  • process and store valid data;
  • maintain an audit trail that records every change made to the data;
  • generate reports and send email notifications to users.

Main frontend

The main frontend is the primary user interface for medical staff. Through a web browser, authorized users enter data required by the study protocol and receive real-time feedback on whether that data complies with the protocol. The frontend is also where users and their roles are managed for a given study. It communicates with the backend exclusively through the HTTP API.

Configurator

A Rodano instance needs a configuration file to start. This file defines every setting and entity required for a given study, and is prepared by data managers with the necessary domain knowledge. The Configurator is the tool used to author it. It can run in two modes: standalone, to create a new configuration from scratch, or hosted by a Rodano server, to edit the configuration of an existing study. The resulting file is then loaded by the backend to run the EDC system for that study.

ePRO

ePRO (electronic patient-reported outcomes) is a mobile web application that lets study subjects contribute data directly, without going through a member of staff. Like the other frontends, it communicates with the backend through the HTTP API.

Manager

The Manager is a web application that lets system administrators operate a Rodano instance running in a Dockerized environment. It reports the status of the platform's containers and can restart the application when needed. It also schedules automatic backups, cleans up old ones, and can restore a chosen backup.

Study deployment

When a new study goes into production, its configuration file is first prepared and verified by the client. The study is then deployed with the current version of Rodano.
